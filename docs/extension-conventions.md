# 扩展设计约定

仅在新增角色、修改技能设计、命名或资源时阅读。这里记录作者约定；API 的行为见 [技能 API 与机制](skill-api.md)。

## 设计语义

- 以本次用户给出的技能描述为准。原有代码用于了解现状，不能替代设计要求。
- 「每回合」「每轮」「你的牌」「弃置」「使用或打出」「直到你的下个回合结束」等措辞会影响结算。描述存在多种解释时，先询问用户。
- 自制大招中用文字标记展示剩余次数的「每局游戏限一次」，保留可计数、可补充次数的设计；不要仅因次数为一就改成 `limited`/`awakenSkill`。真正采用官方限定技机制时再使用这套 API。
- 官方技能没有符合设计的版本时，以最接近的官方实现为参考，在扩展内定义独立变体。

## 命名与文本

- 新角色、技能、子技能与持久存储键使用带命名空间的 `prefix_pinyin`，子技能和存储沿用所属技能的前缀。
- 保持现有角色 ID 和技能键稳定；不要为统一命名顺手重命名已有键。中文角色 ID 可以保留。
- 技能描述中的牌名用 `【】`，标记名或需要引号的词用 `「」`；JavaScript 字符串边界使用 ASCII 引号。
- 新增立绘、音频等资源使用 ASCII 文件名，文件后缀与真实格式一致。此约定不要求改名现有中文扩展目录。

## 展示与交付

- 优先复用已有势力和名前缀；确有新设计时再注册。势力、显示名前缀和角色 ID 分别处理。
- 新增资源时同步实际路径和扩展的资源清单；修改扩展元数据时保持 `extension.js`、`info.json` 一致。
- 打包、导入与现有检查入口见 [扩展仓库 README](../README.md)。版本与发布状态直接查当前文件和 Git，不在本说明中维护副本。
- 交付时区分语法检查、自动测试和游戏内验证；只报告实际完成的验证。
